### 2d. Architecture (from README, "Architecture" section)

Source: `gh api repos/ganguydhrubo/sahakarmi/readme`

```text
Electron main
├── local Codex App Server process over stdio JSONL
├── local Claude Agent SDK session over stream JSON
├── ACP agents (bundled OpenCode, Google Antigravity) over stdio
├── persistent bot and mailbox stores
├── secure typed IPC handlers
└── sandboxed WebContentsView browser host
    ↕ typed preload bridge
SolidJS renderer
```

- `src/main`: Electron lifecycle, window security, local protocol, IPC registration, updates.
- `src/backend`: provider adapters, persistence, message scheduling, approvals, the browser host.
- `src/preload`: the typed `window.sahkarmi` API only.
- `src/renderer`: the SolidJS interface. `src/shared`: process-boundary contracts.
- README also says: Google Antigravity and OpenCode are driven over the Agent Client Protocol; Sahkarmi's browser, approval and team tools reach them through a loopback-only MCP bridge; the app opens no application HTTP port.
- Releases are tag-driven; pushing a tag builds the Windows installer in GitHub Actions and publishes it "with checksums, SBOM and provenance attestation". (Checksums and SBOM are visible as release assets; the attestation itself was not independently checked.)
